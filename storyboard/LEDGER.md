## 4. 冷启动续派步骤

1. 读 `AGENTS.md` + `~/.dsh/AGENTS.md` + 本文件 + `HANDOFF.md`。
2. 实测指纹（`md5` / `git log --oneline`）并**核对是否与本文件 §1 一致**；不一致先查是不是有人改过。
3. 跑门禁看现状（**不要信历史数字，自己重测**）：
   ```bash
   node verify/run-all.js        # 或逐张：node verify/card-NN/<harness>.js
   ```
4. 找当前卡的结算状态：有 `verify/card-NN/` 且门禁可重跑 ⇒ 已交付，**独立复核**后判验收；
   没有证据目录但交付物很新 ⇒ 上一轮中途死掉，按"失败"处理（新开 Worker + 恢复卡）。
5. 判验收后回本文件追加/更新台账行；**收尾按全局约定 §2 一次做完**（commit + tag + 显式推送 + 落地 main + `ls-remote` 自证）。

## 5. 契约自律（复述，防止漂移）

- 导演 / 复核者**不写、不改任何代码或素材文件**；台账落盘属**记录**，不是实现。
- **画面好不好看只有人能判**；脚本只判确定性断言。
- 收尾动作按全局约定（`~/.dsh/AGENTS.md` §2）由执行方一次完成，复核者的责任是**核对 `ls-remote` 自证**。
- 上下文稀缺：跑几十轮后换新会话，靠本台账冷启动。
