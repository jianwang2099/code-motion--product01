### 4.1 负向对照（证明门禁真的会红，不是恒真）

**做法**：把五份文档复制到临时目录，往**副本**里注入一个被禁 token，再让门禁去扫那份副本
（`clean-check.js` 支持 `--docs-dir <路径>`）。**版本库里的真文档全程不被触碰**——
这比"改真文件再还原"安全：还原源一旦搞错就是假还原（见下方 ⚠️）。
**这是本门禁自己的"恒真断言"检查**——一条"怎么写都过"的门禁等于没写。

```bash
cd template
# 注入串 = 一个卡编号 token（`卡` + 空格 + 两位数字），此处故意不写成连续字面量
TOKEN="卡"" 01"
rm -rf /tmp/neg-ctl && mkdir -p /tmp/neg-ctl/storyboard /tmp/neg-ctl/verify
cp storyboard/*.md /tmp/neg-ctl/storyboard/     # 副本
cp ROADMAP.md       /tmp/neg-ctl/               # 让 ../ROADMAP.md 解析得动
cp verify/README.md /tmp/neg-ctl/verify/        # 让 ../verify/README.md 解析得动
printf '\n<!-- negative-control --> %s\n' "$TOKEN" >> /tmp/neg-ctl/storyboard/CARD-REVIEWER.md

node verify/tool-01/clean-check.js --docs-dir /tmp/neg-ctl/storyboard   # 期望 exit 1，且只报注入那一条
node verify/tool-01/clean-check.js                                      # 期望 exit 0（真文档不受影响）
```

> **为什么副本要带 `ROADMAP.md` 与 `verify/README.md`**：J3 的链接自洽断言是在**副本目录**上解析路径的。
> 只复制 `storyboard/` 会让 `../ROADMAP.md`、`../verify/README.md` 解析失败，凭空多出 2 条失败
> （实测：只复制 `storyboard/` → `119 passed, 2 failed`，多出的正是这两条链接；补齐后 → `120 passed, 1 failed`）。
> 这不是门禁的 bug，是**对照组没搭对**——做对照时，除被测变量外的一切都必须相同。

> ⚠️ **实测踩过的坑（写在这里省你一次）**：
> 1. **"改真文件再还原"极易假还原**。第一次实测时先注入、后 `cp` 备份，还原回来的是
>    "带注入标记的版本"——**两边都脏时 `md5` 也相等**，光看 md5 会以为还原成功（改用 `cmp` 才暴露）。
> 2. **`git checkout --` 不能用来还原未提交的改动**：本次清洗当时尚未提交，`HEAD` 里还是**未清洗的旧版**，
>    `git checkout --` 会把清洗成果一起抹掉（实测发生过一次）。
> 3. 记忆点：**"还原源"必须是你真正想要的那份状态，先确认它，再开始破坏性操作**；
>    更好的做法是**根本不去动真文件**（本节的 `--docs-dir` 做法）。
> `/tmp` 只作为临时对照副本，不是证据出口——证据在 `verify/tool-01/`。

## 7. 复核发现的缺陷与修订 01（2026-10-09；原 §7 记录保持不动）

> 背景：本次交付在 2026-10-08 完成、已被**另一个会话**补推并快进落地 `main`。
> 2026-10-09 人对产出做复核时发现**一个真缺陷**，本节记录它、修复方式与负向对照。
> **原 §7（收尾记录）与 §6 的数字保持原样不动**（证据纪律：只加不改）——它们的 md5 是**当时**的实测值。

### 7.1 缺陷：全量 runner 发现不了 `tool-*`，却打印「通过」（假绿）

| 项 | 事实 |
|---|---|
| 现象 | `cd template && node verify/run-all.js` → `跑过 0 个门禁，跳过 2 项` / `结果：全部门禁通过 ✔`，**完全不提 `tool-01`** |
| 后果 | 本目录的 **124 条断言一条都没执行**，runner 却报"通过" = **假绿** |
| 根因 | `template/verify/run-all.js` 第 40 行的目录过滤只有 `/^card-/`（不含 `tool-`） |
| 文档/代码不一致 | `template/README.md:51` 声称"自动发现 `verify/card-*/` 与 `verify/tool-*/`"，而代码只发现 `card-*/` |

**归因（如实，不推给他人）**：本次交付的提交信息**声称**做过 `/^card-/` → `/^(card|tool)-/` 的同步改动，
但**实际 diff 里没有这一行**——该文件在我编辑后被另一会话（`feat/visual-regression`，git 无文件锁）整体覆盖，
而我**提交前只看了 `git diff --stat`、没有逐行复查 staged diff**，所以没发现自己的改动被顶掉。
教训：**`--stat` 只能证明"文件动过"，不能证明"动的是我想改的行"**；提交前必须 `git diff --cached` 逐行看关键行。

### 7.2 修订 01 改了什么（只两行 + 两处注释，不夹带）

| 文件 | 改动 |
|---|---|
| `template/verify/run-all.js` | 第 40 行 `/^card-/` → `/^(card|tool)-/`；同步文件头「做什么」、新增「目录命名」约定说明、空态提示语改为 `verify/card-*/ 或 verify/tool-*/` |
| `template/verify/README.md` | 「命名约定」代码块补 `tool-<NN>/` 目录说明；`run-all.js` 一行注明"发现 `card-*/` 与 `tool-*/`" |

### 7.3 修订后的实测（含负向对照，证明假绿真的被消除）

```bash
cd template
node verify/run-all.js --list
# → tool-01: clean-check.js        ← 修订后能列出 tool-01（修订前：这一行不存在）
```
