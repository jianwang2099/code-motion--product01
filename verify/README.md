# verify/ · 验证证据目录（规范）

> **这个目录是证据，不是源代码。** 里面的一切都可以删除后重跑重建，但**不允许只存在于 `/tmp`**。

---

## 为什么需要它

铁律：**如果复核者不能独立重跑一遍，这份"验证"就不算数。**

反面教训：曾经有任务卡要求"不许新建任何文件"，Worker 只能把自检脚本与截图扔进 `/tmp`；
交付时它们全部消失，复核者**无法复核一个已经消失的证据链** —— 在流程上等于没验证。
所以每张实现卡都必须有显式的证据出口。

---

## 命名约定

```
verify/
  card-<NN>/            每张卡一个目录，编号与任务卡一一对应
    README.md           图/断言 → 验收标准的映射表 + 命令级复现步骤
    *.js                门禁脚本（确定性断言，exit 0 = 通过）/ 截图复现脚本
    *.png / *.json      证据产出（文件名自解释，标注实际视口尺寸）
  tool-<NN>/            非卡类工作（工具 / 基建）的证据，编号与该项目的工具序号对应
    README.md           改了什么 / 为什么 / 怎么重跑（含负向对照与指纹）
    *.js                门禁脚本（确定性断言，exit 0 = 通过）
  run-all.js            全量汇总：发现并运行 **card-*/ 与 tool-*/** 下的所有门禁 + **视觉环节**，打印通过率
  visual/               视觉回归（截图 → 图库 → 逐像素比对 → 纳入全量 runner）
    README.md           技术选择 / 比对口径 / 边界 / 冻结纪律（**先读它**）
    visual.js           统一入口：shoot（抓图）/ compare（比对 + 差异图 + 结论）/ all
    visual-gate.js      确定性门禁（跑在**自造样本**上，不需要浏览器 / 预览服务）
    png.js fixtures.js  零依赖 PNG 编解码（node:zlib）+ 自造样本生成器
    baseline/           图库（真实页面抓的图 + 映射表 README.md + capture-run1.json 指纹）
    visual-gate-out/    门禁运行产物（**由代码现算，不入库**；见 `template/.gitignore` 尾注）
```

## 视觉回归（把「人看画面」自动化成「人只看差异报告」）

判定分工不变：**"好不好看/像不像"仍然由人判**，脚本只是把"每张图都要人看"缩小到"**门禁失败时看差异图上的红点**"。

```bash
# ① 确定性门禁（自造样本，无浏览器/无预览服务也能跑）—— 期望 9 passed, 0 failed
node verify/visual/visual-gate.js

# ② 真实页面：截图 → 与图库比对 → 差异图 + 人可读结论
python3 -m http.server 5173 --bind 127.0.0.1        # 前置：预览服务（受管后台作业，别重复启动）
node verify/visual/visual.js all --baseline verify/visual/baseline --out /tmp/dsh-visual-shots
```

口径与产物（完整说明见 [`visual/README.md`](visual/README.md)、映射表见 [`visual/baseline/README.md`](visual/baseline/README.md)）：

| 项 | 值 |
|---|---|
| 容差 `maxDiff` | **8**（逐通道；**±8 不算差异、±9 算差异**，边界由 `visual-gate.js` 断言钉死） |
| 阈值 `maxRatio` | **0.2%**（噪声包络实测 ≤0.057%，真回归实测 ≥0.68% → 取中间；实测表在 baseline/README.md） |
| 钉相位 | 抓图前把方块钉在中轴附近（默认容差 **±4 世界 px**，`--tol N` 可覆盖；噪声的**唯一**来源就是它） |
| 差异图 | `diff/<name>.diff.png`：红点 = 超容差像素，其余压暗灰（差异非空一定可见） |
| 机读报告 | `visual-report.json`（每条验收的差异计数 / 比例 / 判定） |
| 全量接入 | `node verify/run-all.js` 跑视觉门禁 + 真实页面比对；**失败即 exit 1**；预览不可达/图库为空时打 `[SKIP]` 并注明「**没比对 ≠ 视觉通过**」 |

**边界（原理层，别忘）**：像素比对只能抓"**意外变化**"，抓不了"**符合预期但依然荒谬**"（例：皮筋从第一版就跟着球跑，baseline 也长这样，比对永远通过）。
所以**比对通过 ≠ 画面正确**；人的视觉判断不可替代，只是被缩小到了"看哪几张图"。

## 一份合格的证据要满足

| 要求 | 判据 |
|---|---|
| **可重跑** | `node verify/card-<NN>/<harness>.js` 退出码 0 表示全通过 |
| **自解释** | 截图/产出文件名说清它证明什么；README 里有映射表 |
| **尺寸可信** | 标注的是**页面内实测值**（`window.innerWidth/Height`），不是命令行参数 |
| **驱动真实交付物** | 脚本驱动真实产物（不复制、不注入），否则证明的不是交付物本身 |
| **零副作用** | 重跑不改动实现文件；跑完指纹（md5）与记录一致 |
| **判定分工明确** | 确定性断言由脚本判；**"好看/像不像"由人看截图判**，脚本不代替人的视觉判断 |
| **冻结纪律** | 一经验收即冻结、只加不改；数字过时用**新增章节**说明取代关系 |
| **取代可归因** | 旧断言被新需求推翻时，逐条写清"谁取代了谁、为什么不是回归" |

## 两条最容易被忽略的

1. **恒真断言**：看起来在断言，其实怎么写都通过（例：断言一个恒为 `null` 的字段）。
   审卡阶段的专职检查项。
2. **只测了快乐路径**：门禁必须包含**反面断言**（不该发生的事确实没发生），
   例如"拖拽中的球压在目标上不应触发爆炸"。
